# P2.1.1 supervised daily schedule
Default disabled. Local operator uses existing direct-loopback X-Water-Bench-Key authentication, no proxy/browser. Requires WaterBench Enabled and, for dispatch, EnableSupervisedControl. No autonomous wet chemistry; the schedule creates due slots automatically and requires explicit local approval during the configured grace window. Firmware still requires routing, mixing, powder, camera and cleaning confirmations. Kiosk does not invent measured profiles; stage all three profiles and perform verified cleaning/reset first.

PUT /api/water-bench/schedule with {"enabled":true,"times":["07:00","19:00"],"graceMinutes":5}. Example only, choose farm times. Times are fixed Vietnam UTC+07:00, no DST, 1–8 unique HH:mm daily times, grace 1–15 minutes, nonoverlapping including midnight. GET /api/water-bench/schedule exposes nextDueUtc, lastSlot, state, readiness and storage health. POST /api/water-bench/schedule/approve with {"slotId":"<actual UUID>"} only within that occurrence's window. Sends scheduled mask 7; HTTP 202 means UART write, not firmware acceptance. A direct explicit scheduled command remains available for supervised operation and has the same readiness checks; it is not a calendar occurrence. Before approval, ensure operator is present and physical route/waste/optics verified.

Readiness requires both configured inventory identities, output/RS485 and camera flags, control enabled, no fault, no held or pending batch, available evidence storage, fresh batch idle and clean ready reports and telemetry within 15 s, all 7 pumps calibrated, link healthy, local/remote disarmed and dirty mask 0. Read-only probes while a slot is due, every 5 s. Firmware independently validates profiles and exact dosing volumes. Start pending blocks another start and other normal commands until BATCH START or explicit preflight rejection; STOP remains best effort. No automatic retry. Uncertain command requires physical inspection and controlled restart; exact command-response correlation remains P2.1.2.

Journal in water-bench-spool/schedule/schedule.json, exclusive file lease, temp file flush and atomic rename on same filesystem. Persist consumed slot before attempting UART, UUID reused as audit ID. Status due, expired, missed, interrupted, dispatch_attempt, sent_unconfirmed or blocked. Config updates cancel pending approval and only allow future slots. Backward clock cannot replay consumed due time. On restart, existing due/dispatch_attempt marked interrupted; no catch-up of earlier slots. Long outages coalesce missed occurrences to latest (not a full audit of each missed day). Failed journal locks scheduling, no automatic repair. Filesystem-level power-loss durability requires P3 validation; protect local folder and backups. No automatic cloud upload, no automatic reconnect or resume. Windows and Linux tests; firmware unchanged.

## P2.2.2 Backend-owned mode (opt-in)
Set WaterBench__UseBackendSchedule=true and WaterBench__BackendStationId to the registered station UUID, plus existing exact master/slave hardware IDs and provisioned Kiosk credential. Requires HTTPS backend URL and paired BE P2.2.2. Every 10s GET /api/edge/water-bench/configuration; redirects disabled. Validate station, hardware, mode, version, calendar and three target calibration IDs; persist revision and hash in local schedule journal. Same-version changed content or rollback rejected; expired calibration effective disable may change without revision. On failure, missing station, stale config (30s) or restart before sync, inhibit new scheduled approvals; no replay/catch-up after recovery. Local PUT schedule and direct scheduled command blocked in remote mode. Explicit local approval still required. Manual supervised commands remain independent; revoke/disable is not physical STOP. Local status reports applied revision; no server-side applied ACK yet. Backend configuration does not automatically stage measured firmware pump profiles or validate actual chemistry. Do not activate mode until both CI pass and supervised commissioning.
