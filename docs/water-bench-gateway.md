# P2.1.2 UART command acknowledgments
Requires paired firmware gateway protocol v1 (hardware PR #13). Older firmware remains read-only at Kiosk; no fallback to raw mutating commands. Two physical UART ports as before; no cryptographic UART authentication. Gateway handshake uses random nonce, firmware random boot_id and last_seq. Strict next sequence and UUID32, one outstanding mutating request, persistent attempt before write, immutable outcome. HTTP 202 means written, not accepted. GET /api/water-bench/command/{requestId} (same loopback key) returns attempt and outcome; accepted/rejected are explicit firmware handler outcomes, not proof of physical completion. Missing outcome = uncertain after restart, never replay. ACK timeout 10 s, boot/sequence mismatch or unexpected ACK locks commands until inspected and controlled restart. No auto reconnect, no replay. STOP raw best effort even on fault, not a verified physical stop. Read-only probes raw; exclusive access, no concurrent serial terminal or old Kiosk. Firmware sequence prevents repeating same frame within boot; Kiosk durable UUID journal prevents same request sent again. Boot identity prevents old boot frames. Schedule slot ID equals command Request ID; slot remains sent_unconfirmed; query command journal for outcome. Full schedule lifecycle aggregation deferred. 
Clock observation from nonce handshake midpoint of Kiosk UTC send and monotonic RTT (<3s), refreshed every 60s when no command pending. Detect boot/sequence mismatch and gross clock step during handshake. Store boot and anchor, estimated UTC for NH3 sample/pH/temp observation and ACK uptime; wrap-aware bounded 30min mapping, no claim of validated oscillator drift, hydraulic alignment or actual camera exposure. Existing raw evidence and capture association retained. No sample time invented for NO2/NO3. P3 validate clock drift, UART timing, loss/reboot and physical safety. P2.2 will integrate durable upload, registration and cloud commands.

## P2.2.6.1 — durable local sync queue
The immutable typed timeline and committed media manifests are the outbox; no second SQL queue or deletion. One BenchSyncQueue per WaterBenchSession/spool. On each scan, bound file count/metadata, check filename identity, receipt hash and station, group by boot+batch, require one connection and contiguous start/sequence, block gaps or duplicate capture identity, require matching image request before media. Unknown/corrupt metadata or receipt blocks globally; other station entries are retained but never selected. Plan emits at most one ready candidate per valid batch, timeline before media. Prepare rechecks candidate and image bytes, CRC/SHA/decode. Accept is internal only for a future authenticated server response: validate event/receipt/media/hash, persist immutable receipt atomically, never rewrite evidence; restart reconstructs state. No HTTP sender or retry timer in this step. New queued entries reserve a file and 2048 bytes for receipt; existing entries reserve on restart, old over-quota spools may still require operator capacity intervention. Receipt and capture writers share quota lock; one Kiosk process must own the spool; no auto purge or compaction. Local authenticated GET /api/water-bench/sync/status returns aggregate counts, not evidence/keys. Scan is on demand, O(file count) bounded at 100000 files, no long serial session lock. Pending/acknowledged counts reflect readable committed typed entries, not all raw files; orphan JPEGs/raw evidence remain retained and excluded. Tests cover restart, sequence, wrong station, corrupted receipt, media ordering/in-flight ACK and quota. Transport, timeouts/backoff, NH3 sample ingress, authenticated response verification, multi-process locking and retention/reconciliation remain later stages.

## P2.2.6.2 — automatic typed batch sync (opt-in)
Set WaterBench:Enabled and WaterBench:EnableBatchSync=true, pin BackendStationId, provision kiosk secret and use HTTPS EdgeGateway:BackendUrl (root or /api). Default false. Worker only POSTs typed batch timeline to /api/edge/water-bench/batch-events using X-Kiosk-Key. Named client disables redirects/cookies, 8s timeout, 16KiB response bound. One in-flight event globally, no UART or media POST. Validate HTTP 200, JSON success, same event ID, nonzero receipt ID, duplicate boolean, no media fields; queue writes receipt atomically before selecting next event. Lost response retries unchanged event ID/body; backend idempotency handles committed retry. Basic pacing 1s after receipt, 10s idle/media only, 30s failures including auth/conflict. A rejected oldest batch may block later batches until next retry; per-batch backoff/quarantine and durable retry policy P2.2.6.5. Local status exposes transport state, last attempt/receipt and HTTP status without secrets. Status timestamps are process-local; durable counts from receipts. No production enablement or actual HTTP/DB integration verification; tests use fake handler, no real credential. Old data retained, no commands replayed, physical/chemical completion unverified. Media and NH3 sample sync follow.

Extend the existing single worker, never spawn a second uploader. Typed timeline candidates take priority; media is selected only by the existing queue after matching image request and acknowledged timeline prefix. Same-origin POST /api/edge/water-bench/media, bounded JSON 96 KiB, validates original JPEG SHA/CRC/decode before send. Per-request deadlines 8s timeline / 60s media (client cap 65s), 16KiB response bound, no redirects/cookies. Require HTTP 200, exact event/receipt/media IDs and digest, duplicate boolean; persist immutable receipt before next item; retry identical payload on lost response. Backend owns Google Drive private upload and readback; Kiosk never receives Drive credentials or storage IDs. Status shows effective media enablement. Raw files retained. Tests fake HTTP responses and validate order, default disabled, original JPEG, restart, bad receipt, lost response and corrupted bytes. No real Drive upload, no production switch changes, no chemical validation. Batch-first priority may delay media under continual events; global failure pacing/per-batch isolation and retention still follow. Existing queue may defer an in-flight receipt if unrelated evidence becomes invalid, safe retry rather than false acknowledgment. No DB migration or backend changes in this stage.
